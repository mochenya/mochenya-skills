# 架构笔记质量门

这是交付前的最小检查集。它验证结构和证据边界，不把静态检查误写成运行时正确性。

## A. 仓库证据

- [ ] 仓库路径、分析日期、版本和 commit 已记录。
- [ ] 适用的 `AGENTS.md`、README、元数据和官方架构文档已读取。
- [ ] 总览中的主要入口、窄腰和主生命周期都能定位到源码。
- [ ] 关键结论有调用方或结果消费者，不只引用孤立定义。
- [ ] 源码、测试、文档和配置的冲突已单独列出。

## B. 解释质量

- [ ] 每篇笔记先说明问题和边界，再引入术语。
- [ ] 关键术语使用英文正式名和中文规范定义。
- [ ] 至少一条控制流、数据流或状态转换可以由文字和代码推演。
- [ ] 代码摘录是原始片段，路径和行号可回查；省略处明确标记。
- [ ] 每个核心模块都写了输入、输出、状态、不变量和失败路径。
- [ ] Mermaid 只辅助复杂关系，没有代替机制解释。
- [ ] 工程迁移部分同时写收益、成本、边界和不适合的替代方案。

## C. Obsidian 结构

- [ ] 每篇有 YAML frontmatter、一个 H1 和清晰的 H2 层次。
- [ ] 同一分析集内的 wikilink 全部可解析。
- [ ] 总览指向模块，模块回指总览或相关机制，迁移笔记汇总取舍。
- [ ] 笔记可以脱离聊天上下文阅读，不依赖“上文提到”。
- [ ] UI/皮肤等排除项没有混入核心架构，除非用户要求。

## D. 运行时声明

把结论分为：

| 标签 | 含义 |
| --- | --- |
| `confirmed` | 当前源码、测试或实际运行直接支持 |
| `inferred` | 根据多个源码事实推导，但没有直接运行证据 |
| `needs-runtime-check` | 依赖外部服务、平台、模型、配置或尚未执行 |

没有执行代码时，不写“运行结果是”；写“源码路径表明”或“预期行为是”。

## E. 自动检查

从 skill 目录调用：

```powershell
pwsh -NoProfile -File .\scripts\validate_architecture_notes.ps1 `
  -NotesPath 'D:\System\Documents\Obsidian\Code Learning\Hermes' `
  -RepoPath 'D:\Project\hermes-agent' `
  -RequireMermaid
```

脚本检查 frontmatter、围栏配对、Mermaid 存在性、内部 wikilink 和形如 `path.py:123` 的源码引用是否可回查。它不能验证解释是否正确，也不能替代测试或人工阅读。
