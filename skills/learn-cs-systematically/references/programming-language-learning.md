# 编程语言学习：设计、语义与工程使用

用于整门语言的学习规划、语言特性的设计依据和跨语言语义比较。这里提供语言特有的分析维度，不要求每次讲解都从语言哲学开始。

## 整门语言的覆盖检查

以下维度用于发现课程缺口，不是固定章节顺序或每章必答清单。按学习目标确定范围与深度。

| 维度 | 需要建立的理解 |
| --- | --- |
| 设计问题与取舍 | 语言面向什么问题；安全、性能、表达能力、简单性与兼容性如何影响选择 |
| 计算模型与范式 | 用什么实体、操作与状态描述计算；用什么方式组织程序 |
| 核心概念体系 | 值、类型、绑定、可变性、相等性、作用域、生命周期、函数及该语言特有的数据模型 |
| 语言语义 | 名称查找、求值、类型规则、状态、控制、错误、资源与并发的可观察行为 |
| 工作机制 | 当前抽象层中的规则怎样沿执行、数据流或状态变化产生结果 |
| 编译器与运行时实现 | 具体转换、数据结构和算法怎样实现语义，以及影响哪些诊断或性能判断 |
| 语法与操作 | 声明、表达式、控制流、函数、类型、模块、标准库及惯用写法 |
| 工程实践与生态 | 构建、依赖、测试、调试、发布，以及资源、错误、性能和维护成本的选择 |

这些维度相互关联。例如，计算模型描述怎样表示和推进计算，编程范式描述怎样组织程序与解决问题；二者不是普遍同义词。一门语言也可能支持多种范式。

基础课程应建立关键模型并进入真实操作，不必先学完实现细节。课程归属与重点依据需要进一步规划时，参见 [学习架构](learning-architecture.md)。

## 解释设计：区分历史依据与机制分析

根据当前问题建立“约束—候选方案—选择—收益与代价”的关系，避免用宏观价值观把所有语法事后解释成必然结果。

- 问设计者当时为什么选择，需要正式设计文档、RFC、设计者材料或历史记录支持。
- 分析现有方案有什么收益和代价，可以依据语义与约束推理，但应明确这是分析，不是假定的设计意图。
- 兼容性、生态或实现限制可能解释某个行为，不必把它包装成统一理念或最优设计。
- 替代方案应在相关约束下比较，不用脱离场景的优劣排行榜。

“没有这个设计会怎样”可以帮助显现它解决的问题，但反事实分析不能替代历史证据。

## 区分语义、机制与实现

**语义**说明代码按照语言规则意味着什么、允许或保证什么行为。**机制模型**追踪相关规则怎样产生结果。**具体实现**说明某个编译器、解释器或运行时采用的数据结构、转换与算法。

讲解时先建立所需的实体和规则，再决定是否下沉到实现。例如，闭包主题可能需要解释词法关系与被保留的绑定；是否进一步讨论环境对象布局，取决于它能否解释当前的行为或性能问题。

同一语义可能有多种实现。不要把某个编译器或运行时的常见做法当作语言保证，也不要因表面语法相似就假设不同语言共享同一个执行模型。

只有当实现细节影响当前的行为解释、诊断、资源成本或工程选择时才展开。小解释器或实现实验可以帮助理解，但不是学习语言的必经步骤。

## 连接真实写法与工程判断

在概念与机制基础上，展示完成当前任务需要的语法、参数、返回值、状态影响和错误边界。涉及一组常用操作时，参见 [语法与操作](syntax-and-api-teaching.md)，不能用几个示范调用替代声明范围内的操作面。

存在工程选择时，说明：

- 哪些约束由语言或类型系统保证，哪些仍需要运行时验证、测试或团队规范。
- 当前特性适合解决什么问题，代价落在哪里。
- 什么条件变化后应考虑替代方案，怎样观察或验证。

语言允许某种写法不等于工程上推荐它，更不等于项目必须采用某种架构。

## 跨语言比较

先确定共同问题，再选择会改变行为或选择的维度，例如：

- 实体存在于编译时还是运行时。
- 值、绑定、对象身份与可变性的关系。
- 名称查找、调用、方法派发与作用域。
- 类型检查、类型擦除与外部输入验证。
- 生命周期、资源所有权与清理。
- 错误传播、并发、异步与调度。
- 语言保证、实现行为与生态惯例。

比较应揭示相同术语下的语义差异，而不是罗列关键字。遇到“只是语法糖”时，说明相对于什么目标语义、在哪一层成立，以及它解释不了什么。

## 证据职责

| 要说明的内容 | 优先依据 |
| --- | --- |
| 设计目标与历史选择 | 正式设计文档、RFC、设计者材料、历史记录 |
| 语义与保证 | 规范、标准、官方语言参考 |
| API 与工具行为 | 目标版本官方文档、相应环境测试 |
| 编译器与运行时实现 | 实现文档、源码、诊断与可重复实验 |
| 工程建议 | 明确场景、约束、测试或性能数据 |

语言版本、具体实现与规范层结论不一致时，先限定适用范围。阶段能力应体现理解与操作的结合：能依据模型预测结果，写出自然任务所需的代码，并说明相关边界；不以“看完语法”作为掌握证据。
