# Obsidian 学习笔记

仅在用户明确授权创建或更新笔记时使用。本文件负责持久化与笔记组织，不另设一套教学流程。

## 范围与知识沉淀

确认目标 Vault、相对路径或允许操作的目录，以及读写范围。只在授权范围内查重与复用已有笔记；范围不明时询问，不因 CLI 或文件系统可访问就扩大阅读。

优先更新同一主题的已有笔记，避免重复创建。普通聊天、临时调试输出和学习者画像不自动写入。保留稳定、可复用的知识，不复制聊天逐字稿。

一篇笔记围绕连贯问题、模型或操作族；宽主题用地图连接章节。尊重现有知识库约定，不为套用本文件而批量修改无关笔记或属性。

## 按用途形成可独立阅读的内容

- 新学笔记：声明必要前置与本篇范围，建立概念、关系和机制，再连接例子及操作。
- 复习笔记：恢复核心模型，突出容易混淆的条件、边界与选择；按需提供自检和展开阅读的位置。
- 两者都应保留当前推理所需的定义与关系，不能用链接代替关键解释。
- 独立可读面向目标读者，不等于每篇从零重讲全部基础。

正文组织需要进一步指导时，参见 [教学表达](teaching-style.md)。需要起草骨架时再使用 [轻量笔记模板](../assets/systematic-note-template.md)，根据用途调整；不要求既有笔记重新套模板。

## 属性与名称

现有 Vault 的属性约定优先。没有约定时，可使用：

~~~yaml
---
title: "中文标题"
tags:
  - cs/domain
type: concept
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
~~~

标题采用通行且准确的名称；有检索价值的英文名、缩写或其他译法放入 aliases。标签使用低基数领域分类。type 根据用途选择 concept、chapter、lab、practice、exercise、project 或 reference。

仅在影响内容时添加 version。日期依据实际创建与修改情况填写，更新已有笔记时保留创建日期；不要添加空属性或为排版造字段。

## 链接与参考

- 前置、相关与后续知识使用 wikilinks；只链接范围内确认存在或已明确规划的目标，不为关系图丰富而制造占位链接。
- 外部来源使用 Markdown 链接，保留真正支持内容或进一步学习的资料，不要求凑固定数量。
- 规范、版本或有争议的结论在附近给出必要依据；普通笔记不必变成逐句引用审计。
- 不为统一术语或修复其他链接越出授权目录。

## 轻量排版

使用一个与 title 一致的一级标题，层级连续。正文以短段落为主，列表整理并列项，表格用于比较。标题可以概括主题，也可以表达具体问题，不强制每节使用问句。

Callout 只用于值得突出或折叠的内容，例如关键误区、示例或自检答案；不默认把结论、环境和普通正文全部装进提示块。图表仅在显著帮助理解且载体支持时使用。

验证可以紧邻例子，自检可以嵌入相应段落，工程边界可以随机制解释；不强制分成独立章节。复习摘要不套用完整新学长文的结构。

## 交付检查

确认路径、读写范围和既有约定得到遵守，正文适合所声明的学习用途，核心关系不依赖聊天背景，链接与属性有效，模板提示和占位内容已清理。

涉及代码执行或结果声明时，遵守主文件的证据边界；需要复现实验细则再参见 [代码与证据](code-style.md)。写完笔记不表示已验证用户掌握。
