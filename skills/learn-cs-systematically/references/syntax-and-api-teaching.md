# 语法、方法与 API 操作讲解规范

当前主题是语法结构、数据类型、集合、标准库、API、SDK、CLI 命令族或“有哪些常用方法、怎样调用”时读取本规范。目标是在概念模型中把真实操作讲完整，而不是在“只讲机制”和“罗列名称”之间二选一。

## 概念优先不等于操作稀薄

先说明操作服务于什么问题、对象或数据模型，再讲调用和结果；但如果当前学习目标就是会使用一个类型或 API，就必须覆盖完成常见任务所需的核心操作。

示例最小表示删除无关项目搭建，不表示只挑一两个方法。内容过多时按用途或生命周期拆成连续章节并说明归属，不能为了篇幅静默省略，也不要机械地“一方法一篇”。

## 先确定操作面和声明范围

根据当前权威文档和目标版本检查相关类别：

- 构造、初始化和字面量形式；
- 静态函数、属性或命令入口；
- 实例属性和实例方法；
- 运算符、索引、迭代协议和转换；
- 回调、事件、生命周期钩子或异步结果；
- 空值、无结果、错误、清理和资源行为。

不要凭记忆声称已经列出完整 API。先声明本篇覆盖的版本和范围，再把成员分类：

- **核心操作**：完成当前学习目标必需，提供完整操作契约；
- **辅助操作**：主线自然需要时讲清，不扩张成独立目录；
- **扩展操作**：说明它解决的问题并放入后续；
- **明确不讲**：当前不需要，不能暗示已经完整覆盖。

“常用”应由真实任务、生态惯例、相邻方法的选择需求和当前学习目标共同决定，不只依据方法出现频率。

## 按问题和生命周期分组

优先按操作意图组织，而不是按字母顺序平铺名称。根据主题选择类似结构：

```text
创建
→ 检查
→ 查询
→ 新增或更新
→ 删除
→ 遍历
→ 转换
→ 聚合
→ 清理或结束生命周期
```

同一组内突出相近方法为什么不同。导航表可以概括用途、返回值和是否修改状态，但不能代替核心操作的代码、结果和解释。

## 语法结构的讲解契约

讲解语法结构时，根据相关性说明：

1. 最小合法形式和完整常用形式；
2. 必选部分、可选部分和默认行为；
3. 每个位置能够出现什么表达式、类型或标识符；
4. 求值顺序、作用域、控制流或类型规则；
5. 该语法产生值、语句效果、类型信息还是运行时对象；
6. 失败时是语法错误、静态诊断、运行时异常还是无结果；
7. 与相近语法形式的选择差异；
8. 一个自然示例、结果和关键边界。

不要只展示“怎么写”，也不要为了讲设计思想而不教学习者怎样正确写出它。

## 核心操作的 API 契约

API contract（API 契约：一个操作对调用形式、输入、返回值、状态变化、错误和边界行为作出的可验证约定）至少按相关性说明：

1. **主要用途**：它解决哪类自然任务；
2. **调用形式**：准确的最小调用和常用形式；
3. **接收者或上下文**：方法作用于谁，命令在哪个上下文执行；
4. **参数**：位置、名称、接受的输入、默认值和可选项；
5. **回调参数**：回调何时调用、依次收到什么、返回值怎样被使用；
6. **返回值或输出**：类型、内容、无结果表示和标准输出/错误；
7. **状态影响**：是否修改原值、保持身份、创建新值、分配或释放资源；
8. **错误与边界**：空集合、缺失值、非法输入、异常、退出码或取消；
9. **自然示例**：使用真实任务和稳定、可观察的结果；
10. **相近选择**：什么时候用它，什么时候另一操作更清楚或安全。

不是每个辅助操作都需要十个可见小标题，但核心契约中的行为不能因为排版压缩而消失。

## 同时展示返回值和状态影响

对会返回结果或改变状态的操作，优先展示：

```text
调用前
→ 调用表达式与参数
→ 返回值或输出
→ 调用后
```

特别区分：

- 修改接收者与返回新值；
- 浅复制、深层对象共享与对象身份；
- 方法自身的行为与回调造成的副作用；
- 找不到、返回空集合、返回 `undefined`/`null` 和抛出异常；
- 返回修改后的对象、返回删除内容、返回布尔状态或无返回值。

实际代码、环境、运行命令和输出遵循 [code-style.md](code-style.md)。

## 比较容易混淆的操作

只有名称列表不足以支持选择。把解决相邻问题的方法放在一起比较，并使用同一输入观察差异，例如：

```text
转换全部元素 vs 只执行副作用
返回第一个匹配项 vs 返回所有匹配项
复制一个区间 vs 原地删除或替换
判断至少一个满足 vs 判断全部满足
原地更新 vs 创建新集合
```

比较维度优先包括：输入、返回值、是否修改原状态、短路行为、无结果行为、错误边界和主要用途。

## 校准示例：JavaScript Array 章节

系统讲解 JavaScript `Array` 时，先说明数组的数据模型和可变性，再根据当前官方文档与目标版本建立操作面。常见课程可以按以下问题分组，而不是只挑 `push`、`map`、`filter` 三个方法：

```text
怎样创建和识别数组
怎样读取、定位和判断元素
怎样增加、删除和替换
怎样截取、组合和复制
怎样遍历、转换、筛选和聚合
怎样排序，以及原数组会不会改变
空数组、找不到元素和回调分别怎样表现
```

应重点比较会改变选择的相邻操作，例如 `map` 与 `forEach`、`find` 与 `filter`、`slice` 与 `splice`、`some` 与 `every`。这个列表用于校准教学深度，不是永久、完整的 API 清单；实际内容必须查询当前权威资料。

同一组数据可以支持多个短示例。每个核心方法至少让学习者看到调用形式、参数或回调参数、返回结果、原数组变化和主要用途。

## 使用多个短示例而不是重复搭建

单一机制可以围绕一个代表性示例展开；方法族因为契约不同，通常需要多个微型例子。优先：

- 复用同一份输入数据；
- 每个示例只隔离一个行为差异；
- 在代码旁标注调用前、返回值和调用后状态；
- 先预测结果，再运行或推演；
- 用一个边界变式检验是否真正理解契约；
- 最后用一个自然任务要求学习者选择合适操作。

不要为展示数量复制大量几乎相同的代码，也不要让一段综合代码同时首次引入十个未解释的方法。

## 版本、来源和完整性声明

库、框架、SDK、API、CLI 和持续演化的语言内建功能必须查询当前权威文档。说明目标版本或运行环境，并区分：

- 当前规范或官方文档列出的能力；
- 具体运行时已经实现的能力；
- 生态惯用法；
- 本篇选择为核心、扩展或明确不讲的内容。

资料冲突时，用最小可复现实验确认目标环境，不把多个版本的行为混在同一契约中。

## 完成条件

一个语法或 API 操作主题完成后，学习者应在当前范围内能够：

- 写出核心语法或调用形式；
- 解释主要参数、回调参数和默认行为；
- 预测返回值、输出和状态影响；
- 在相近操作之间做出选择并说明理由；
- 识别空值、无结果、错误和版本边界；
- 修改或组合核心操作完成一个自然任务。

“知道方法名”或“复制示例能运行”不能单独作为完成标准。
