# 语法与操作契约

用于系统讲解语法结构、数据类型、集合、标准库或 API、SDK、CLI 的常用操作。重点是把操作放回概念模型，而不是在“只讲原理”和“只列名称”之间二选一。

## 以任务确定操作范围

根据目标版本的权威资料，检查当前目标需要哪些操作：创建、读取、查询、修改、遍历、转换、聚合、错误处理或资源清理等。只检查适用于目标对象的类别，不把所有主题强行套进增删改查。

区分：

- 核心操作：完成当前目标必需，讲清必要契约。
- 辅助操作：主线自然需要，解释到足以正确使用。
- 后续内容：说明用途与归属，不暗示已经覆盖。

“常用”由实际任务、生态惯例和相邻选择决定，不仅是出现频率。用户要求整组方法时，不以少数示例代替完整范围；只问一个调用时，也不默认展开整个 API。

范围过宽时按用途或生命周期分组，明确本次完成什么；不要凭记忆声称穷尽全部成员。

## 语法结构：写法与含义一起解释

根据主题选择需要说明的部分：

- 最小合法形式、常用形式、必选与可选部分。
- 每个位置接受什么，默认行为是什么。
- 求值顺序、作用域、控制流或类型规则。
- 产生值、状态效果、类型信息还是运行时对象。
- 失败发生在哪个阶段，与相近语法有什么区别。

形式、含义和结果应相互支撑。不要只展示代码，也不为讲设计思想而省略正确写法。

## 操作契约：抓住会改变使用判断的信息

核心调用按相关性覆盖：

| 信息 | 需要说明的内容 |
| --- | --- |
| 用途与上下文 | 解决什么任务，作用于谁，在什么环境中调用 |
| 调用与参数 | 形式、输入要求、默认值、可选项及回调语义 |
| 结果 | 返回类型、值或输出，无结果怎样表示 |
| 状态与资源 | 原状态是否改变，是否产生新值、共享对象或分配、释放资源 |
| 错误与边界 | 空值、非法输入、失败、取消或清理的行为 |
| 相近选择 | 什么条件下另一种操作更合适 |

这些是内容检查维度，不是每个方法的固定标题。共享契约可以集中讲解，各操作只突出差异；不能因压缩而省略决定正确使用的行为。

## 用结果与状态展示区别

操作返回结果或改变状态时，按需展示“调用前—调用—返回值或输出—调用后”。重点区分：

- 修改接收者与创建新值。
- 浅复制与深层对象共享。
- 操作本身的效果与回调产生的副作用。
- 无匹配、空结果、空值和异常。
- 返回值与修改后的状态是否相同。

相近方法优先使用相同输入比较；例如查找一个与筛选多个、复制区间与原地替换、判断任一与判断全部。让差异来自契约，而不是不必要的数据变化。

## 示例数量服从操作差异

单一机制可围绕一个代表性例子；不同契约通常需要多个短例子。复用输入与准备工作，每个例子隔离重要差异，避免综合代码一次引入大量陌生调用。

例如，规划数组操作章节时，应根据任务检查创建、查询、修改、复制、遍历、转换和排序等相关操作，而不是只展示几个熟悉的方法。这是覆盖校准，不是跨语言统一或永久完整的 API 清单。

按需用边界变式或自然任务检验学习者能否选择与组合操作，不强制每个方法附完整练习。需要执行环境与结果呈现约定时，参见 [代码与证据](code-style.md)。

## 来源与完成范围

区分规范列出的能力、目标运行时已实现的能力和生态惯用法。资料冲突时先定位版本与环境差异；在安全且已授权的环境中，必要时用最小实验核对，不能仅凭一次观察推翻规范保证。

交付前检查：声明的核心操作是否足以支持目标任务，读者能否找到调用方式、主要输入输出、状态影响与相近选择。提供了这些内容不等于已经观察到学习者掌握。
