# 概念优先教学方法

用于系统讲解、教材级笔记和任何包含隐藏前置知识的核心主题。目标不是让学习者记住 API 或模仿代码，而是让他能够从概念和规则推导新行为。

## 主动发现未知缺口

不要假设学习者会说出缺少的名词。开始前识别理解目标问题所需的术语，并分类：

- **主概念**：当前内容必须完整讲透；
- **必要前置**：给出足以理解本文的最小回顾；
- **已声明前置**：明确指出依赖、说明其必要性并提供后续入口；
- **延伸概念**：在主线完成后再链接，不抢占当前解释。

在正文早期给出小而准确的“核心概念地图”。地图用于让学习者看到接下来会遇到什么；它不能替代定义。

## 主概念六问

每个主概念都应回答：

1. **是什么**：给出可与相近术语区分的定义。
2. **为什么需要**：说明没有它时，前一个模型无法解决什么问题。
3. **处于什么位置**：说明它和其他概念、输入、输出或状态的关系。
4. **如何运行**：解释生命周期、状态转移、控制流或数据流。
5. **不是什么**：说明常见混淆、反例或适用边界。
6. **如何验证**：给出可预测的例子、实验、推演或权威来源。

先给正式定义，再给必要的直觉，随后回到机制。不要用口语化重复、无法映射回技术模型的类比或未解释的术语堆砌来制造“易懂”的错觉。

## 学习者适配

学习者状态改变进入方式，不改变主概念图。

- **初学者**：完整定义主概念和必要前置，提供一个完整例子与执行追踪。
- **有基础者**：保留定义和概念地图，把已知语法放入简短“快速回顾”，重点讲机制、边界和工程后果。
- **深挖者**：在压缩回顾后，加入形式语义、实现观察、性能取舍或源码证据；明确语言保证与具体实现行为的差异。

只使用当前请求中给出的背景来调整讲解。不要持久记录个人掌握度或误解历史；可复用笔记通过“最小前置知识”和“快速回顾”服务不同读者。

## 教材完成条件

完成系统讲解或笔记前，检查：

- 主概念是否在首次依赖前定义；
- 概念之间的必要关系是否被解释，而不是只放链接；
- 读者是否能据此预测一个代表性例子的行为；
- 是否给出了少量高价值反例或易混淆边界；
- 自检问题是否能定位具体缺口，而不是只要求“复习整章”。
