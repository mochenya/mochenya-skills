# 概念优先教学方法

用于系统讲解、教材级笔记，以及任何包含隐藏前置、核心机制或错误心智模型的主题。目标不是让学习者记住术语或模仿代码，而是建立能够定义、预测、解释、区分和迁移的模型。

## 从现象或问题进入

先指出学习者实际遇到的现象、限制、失败或判断问题，再确定解释它所必需的概念。不要先堆术语，也不要把“用途很多”“非常重要”当成动机。

如果主题是编程语言设计或语言特性为什么如此，同时读取 [programming-language-learning.md](programming-language-learning.md)；本文件负责概念与机制，不负责还原完整的语言设计历史。

## 主动发现隐藏前置

不要等待学习者准确说出自己不知道的名词。把相关内容分为：

- **主概念**：当前学习结果依赖，必须在本篇完整讲清；
- **必要前置**：给出足以进入当前模型的准确回顾；
- **借用内容**：只为读懂当前例子暂时使用，明确说明正式学习位置；
- **近期后续**：完成当前主线后自然需要的独立主题；
- **远期扩展**：当前结论不依赖，不抢占主线。

初学者可以看到更少的高级分支，但不能缺少支撑当前结论的概念。允许使用准确且有边界的阶段性模型，并明确它还没有解释什么。

## 建立核心概念地图

在正文早期给出小而准确的关系图，说明参与者、依赖、输入输出或状态关系，例如：

```text
lexical scope
      ↓ 决定名称查找范围
lexical environment
      ↓ 在函数值被保留时形成
closure
```

地图只显示当前推理需要的节点和关系，不能代替正式定义。主概念必须在第一次被后续推理依赖之前解释清楚。

## 锚定术语与真实表达

按照 [terminology-style.md](terminology-style.md) 首次建立英文正式名、中文规范名和准确的“是什么”定义。概念存在自然表达时，把最小真实形态放在定义附近：

- 类型系统使用类型标注、签名或判断形式；
- 运行机制使用状态、事件序列或调用关系；
- 算法使用输入输出、不变量或最小伪代码；
- 数据结构使用节点、字段或关系；
- API 和命令使用最小调用形式。

首次定义不要同时塞入完整动机、机制、边界和工程建议；这些关系在正文中分别建立。

## 主概念六问

每个主概念都应回答：

1. **是什么**：给出能够排除相近概念的定义；
2. **为什么需要**：前一个模型、表达方式或工程问题哪里不够；
3. **处于什么位置**：它与参与者、输入、输出、状态和其他概念是什么关系；
4. **怎样工作**：规则、生命周期、控制流、数据流或状态怎样变化；
5. **不是什么**：最容易混淆的说法、反例和适用边界是什么；
6. **怎样验证**：什么实验、输出、诊断、推演或规范关系能够检验理解。

若主概念是某个语言设计选择，“为什么需要”之外还要按 [programming-language-learning.md](programming-language-learning.md) 比较背景约束、替代设计和取舍。

## 建立基本模型并追踪机制

至少说明与当前结论有关的：

- 参与者或实体；
- 输入、输出和初始状态；
- 不变量和前提；
- 名称、值、控制、数据、类型或资源如何流动；
- 哪一步改变状态，哪一步只读取或产生新值；
- 当前结论属于规范语义、教学模型还是具体实现。

沿时间或因果关系逐步追踪，不用一句“底层自动完成”跳过决定结果的步骤。实现细节只有在能够解释可观察行为、性能取舍或语言边界时才展开。

## 用证据形成学习闭环

系统讲解、学习规划或学习者暴露误解时，优先使用：

```text
预测
→ 运行或推演
→ 对照结果
→ 解释分叉点
→ 改变一个条件
→ 再次预测
→ 迁移到自然任务
```

证据可以是可运行示例、编译器诊断、运行时输出、状态表、手工推演、规范条文或实现观察。没有真正执行时必须标为“预期结果”，不能暗示已经验证。

## 可观察的理解证据

根据主题选择必要项：

1. **定义**：说清它是什么，并排除一个相近概念；
2. **预测**：依据规则预测新输入、分支、输出、错误或状态变化；
3. **追踪**：沿执行、数据、类型、控制流或生命周期解释结果；
4. **区分**：说明两个相近概念在什么条件下得到不同结论；
5. **迁移**：修改、实现、调试或选择一个自然任务，并说明约束和代价。

运行过示例只证明示例运行过，复述定义只证明见过术语；不要把其中任何一项单独当成掌握证据。

## 诊断最小缺口

当学习者说“听不懂”或预测错误时，先定位：

- 不认识术语：补名称、定义和最小真实表达；
- 关系不清：补核心地图和参与者；
- 预测错误：补规则、状态、不变量或控制流；
- 单例正确但变式失败：补前提、边界或相邻概念；
- 会解释但不会操作：补语法或操作契约；
- 会操作但不会选择：补问题约束、替代方案、验证和成本。

一次只修复阻塞当前主线的最小缺口，不因为一个错误重新讲完整个领域。语法或 API 操作缺口读取 [syntax-and-api-teaching.md](syntax-and-api-teaching.md)。

## 教材完成条件

完成系统讲解或笔记前检查：

- 当前学习结果依赖的概念是否都在首次使用前定义；
- 核心关系是否在正文中解释，而不是只放在链接或图里；
- 学习者能否据此预测至少一个代表性例子的行为；
- 是否明确了少数决定结论的边界、反例或相近概念；
- 代码、输出或推演是否真的支持所声称的结论；
- 自检是否能够定位具体缺口，而不是只要求“复习本章”。
