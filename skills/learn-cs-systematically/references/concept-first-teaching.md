# 概念建模与理解缺口

用于隐藏前置、复杂机制、错误心智模型或学习者“听懂了却不会判断”的场景。重点是怎样建立和修正模型，不另行规定文章格式。

## 找到决定当前理解的概念

从待解释的现象、限制或判断问题出发，区分：

- 主概念：当前主题本身，需要建立足以解释和使用的模型。
- 必要前置：当前推理依赖，但不是本次主线；按已有理解补足。
- 暂时借用：只为读懂例子使用，简要交代含义和后续学习位置。
- 后续与扩展：不决定当前结论，标明去向而不抢占主线。

不要等待学习者准确说出缺少的术语。也不要仅因内容“基础”就提前展开；判断依据是缺少它是否会阻塞当前推理。

多个实体或依赖关系难以用文字说明时，给出小型关系图。箭头说明具体关系，如“决定名称查找”“持有资源”“触发状态变化”，不只连接名称。图不能替代当前推理所需的定义。

## 用问题检查模型，而不是套六个标题

按当前目标检查哪些问题尚未得到回答：

- 是什么：它属于什么类别，与相近概念怎样区分？
- 为什么需要：原有模型或方法不能解决什么问题？
- 处于什么位置：与其他实体、输入输出或状态有什么关系？
- 怎样工作：哪些规则、事件或操作决定结果？
- 在哪里不成立：关键前提、反例或简化边界是什么？
- 怎样检验：什么推演、实验或新任务能够区分正确与错误理解？

用户只问一个局部问题时，展开决定答案的部分。系统讲解再检查支撑目标能力的关系是否完整，不对每个辅助术语重复六问。

## 让机制可以追踪

选择与结论有关的实体、初始状态、规则和不变量，沿因果关系或执行顺序解释：

- 谁读取、产生或改变了什么？
- 哪一步推进控制流、数据流、类型推导或资源生命周期？
- 什么条件使行为发生分叉？
- 哪些行为属于抽象规则，哪些来自具体实现？

定义附近可放置最小真实表达，如类型签名、节点结构、状态或调用形式。不用“底层自动完成”跳过决定结果的步骤，也不为展示深度展开无关实现。

阶段性模型应说明适用条件和暂未覆盖的重要情况。后续通过增加条件和细节扩展模型，避免先教一个错误结论再要求学习者遗忘。

## 用对照与变式暴露缺口

单个正确例子展示规则如何工作；对照与变式帮助判断学习者是否理解成立条件。根据需要选择：

- 保持其他条件不变，只改变一个输入、状态或前提。
- 比较表面相似、机制不同的两个结果。
- 使用表面不同、核心规则相同的新任务。
- 先预测，再运行或推演，解释预测与结果的分叉点。

这些是可选教学手段，不是必须走完的循环。用户要求直接解释时，给出推演与答案；不为制造互动而扣住内容。实际执行和结果呈现需要更细约定时，参见 [代码与证据](code-style.md)。

## 根据表现修复最小缺口

| 可见表现 | 优先检查与补充 |
| --- | --- |
| 不认识术语 | 名称、定义与最小真实表达 |
| 名词都认识但连不起来 | 实体关系与当前概念的位置 |
| 能复述却预测错误 | 规则、初始状态、前提或控制流 |
| 原例正确，变式失败 | 适用条件、边界或相邻概念 |
| 会解释但不会操作 | 必要语法与操作契约 |
| 会操作但不会选择 | 问题约束、替代方案及代价 |

诊断是暂时假设，应随用户表现修正。只补足阻塞当前主线的内容；不要凭一次回答判定整体能力。操作教学需要进一步展开时，参见 [语法与操作](syntax-and-api-teaching.md)。
