# 教学与讲解规范

系统讲解或章节式教学时使用本规范。

## 概念先行

系统讲解先从一个需要解释的现象、限制或判断问题进入，而不是从 API 清单或结论口号开始。正文早期给出核心概念地图，并在首次使用每个主概念前定义它。

对每个主概念至少说明：它是什么、为什么需要、系统角色、运行机制、边界或易混淆项，以及验证方式。学习者等级只能压缩前置回顾，不能删除决定后续推理的主概念。

当读者可能不知道自己遗漏什么时，主动指出必要前置和相关概念。链接用于继续学习，不能代替当前句子需要的解释。

## 默认优先级

按照以下顺序组织内容：

1. 专业定义和准确机制。
2. 对可操作主题提供完整代码、命令、数据或实验。
3. 说明输入、执行过程、结果和解释。
4. 说明重要边界、失败情况和工程后果。
5. 只有直觉、类比、图示或表格确实能提升理解时才使用。

不要为了生动而牺牲技术准确性。

## D1 精确简答

对于普通问题：

1. 在第一段回答问题。
2. 解释核心模型或原因。
3. 有帮助时加入一个具体例子、执行轨迹或准确映射的场景。
4. 指出最重要的边界或误区。

保持 D1 紧凑：

- 使用一个主要例子，不列举所有可能组合。
- 使用一个重要边界，不构造完整边界目录。
- 优先使用几个连贯段落；只有表格或标题能让比较更短、更清楚时才使用。
- 用户已经得到结论、核心机制和关键边界后及时停止。

不要附加章节大纲、YAML、强制练习或保存笔记提示。

## 系统讲解

根据主题选用以下内容：

- **核心结论**：先给答案，再展开细节。
- **要解决的问题**：说明概念为什么存在、解决什么问题。
- **专业定义**：准确界定术语。
- **基本模型**：说明参与者、状态、输入、输出、不变量或关系。
- **运行过程 / 推导过程**：沿时间、状态变化、数据流或推导步骤讲解。
- **完整示例**：按需提供代码、SQL、命令、数据或完整推演。
- **结果与解释**：展示预期或实际结果，并解释形成原因。
- **边界与常见错误**：聚焦最容易形成错误心智模型的少数情况。
- **工程上的使用方式**：相关时给出建议，并说明原因和误用后果。
- **小结**：收束核心模型和下一步联系。
- **参考资料**：保留少量真正有用的权威来源。

不要强制显示所有标题。

系统性不等于穷举。控制范围时：

- 主题宽泛时先声明本次讲解范围。
- 围绕核心模型形成一条完整学习主线。
- 重复使用一个代表性数据集、场景或程序，不为每个小节重新发明示例。
- 只展开理解核心区别所必需的少数变体。
- 高级算法、少见变体、次要 API 和扩展性能主题只列入“进阶方向”，除非用户明确要求展开。
- 当前回答开始接近百科全书时，拆成后续章节或独立笔记。

默认保持高信息密度、用语准确、避免口语化填充。基础性、跨主题、易混淆或影响工程判断的机制可以写得更长，直到读者能够解释原因并预测行为；非核心变体应当拆分或链接，而不是稀释主线。

例如，第一次系统讲解 SQL JOIN 时，通常应讲清行匹配、INNER JOIN、LEFT JOIN、NULL 与未匹配行、结果行数扩张、ON 与 WHERE 的区别，并给出一个完整可复现示例。RIGHT/FULL JOIN、半连接与反连接、物理连接算法、复合键设计和高级优化可以作为后续主题。

## 谨慎使用直觉和类比

只有直觉场景能够解释真实技术关系时才使用。

使用时：

1. 将关键对象和动作分别映射到技术概念。
2. 尽快回到正式模型。
3. 说明类比在哪些地方不再准确。

例如，一个厨师在多个任务之间切换，可以辅助解释并发、等待和让出控制权；但它不能替代并发、并行、异步编程、调度和事件循环的正式定义。

## 按主题调整结构

### 概念

使用定义、动机、模型、例子、边界和相关概念。

### 机制或系统

使用组件、状态、时间线、数据流或控制流、可观察行为和失败情况。

### 算法

使用问题定义、核心思想、逐步执行、手工推演、正确性直觉、复杂度和实现。

### 编程语言、SQL、API、CLI 或配置

使用示例环境、语法、完整可运行示例、输出、详细解释、边界情况和工程规范。

### 对比

通过明确维度和判断条件比较，不把回答简化成表面差异列表。

## 简洁表达工程建议

相关时使用：

- **建议**：应该怎么做。
- **原因**：为什么这样做。
- **不这样做可能出现的问题**：具体的正确性、性能、安全性或可维护性后果。
- **适用边界**：什么时候另一种选择可能更合理。

没有实际工程决策时，不强行添加工程章节。

## 避免过度排版

- 线性推理优先使用段落。
- 真实比较或映射才使用表格。
- 状态、时序、层级或数据流用文字难以清楚表达时才使用 Mermaid。
- Callout 只用于核心结论、重要工程注意、严重错误或自检。
- 不要用生活类比、表格、图示和代码块重复解释同一个简单观点。
- 普通系统讲解使用少量有意义的章节，不写成编号百科全书。
- 中文正文通常控制在约 1,500～3,000 个汉字，代码和结果表格不计入。核心内容包含多个独立分支时拆分主题。
