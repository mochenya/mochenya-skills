# 学习架构：范围、依赖与覆盖

在用户开始学习一门新语言或宽主题、请求重点/进阶路线、比较教程、暴露“只会调用但不知道还缺什么”，或需要规划多章学习材料时读取本规范。本文件决定课程或学习路径覆盖什么、先后关系是什么、内容归属在哪里；不规定最终文章的固定标题。

## 建立学习契约

先根据当前对话明确：

- 学习主题、实际边界和暂不涉及的内容；
- 学习者已经明确具备的前置知识，以及不能假设其具备的内容；
- 目标能力，例如阅读、编写、调试、比较、设计或工程使用；
- 语言、运行时、平台、工具链和版本范围；
- 需要概念深度、操作覆盖、实践密度和工程方向到什么程度；
- 什么可观察表现代表当前阶段完成。

学习者背景改变前置回顾、语法解释和执行追踪的密度，但不能改变正式定义，也不能静默删除支撑目标能力的核心概念或操作。不持久记录当前分数、误解、复习日期或对话性画像。

## 建立覆盖清单

宽主题开始批量写作前，先建立小而明确的覆盖清单。每个重要概念或操作至少判断：

| 字段 | 要回答的问题 |
| --- | --- |
| 概念或操作 | 学习者必须理解什么或能够完成什么？ |
| 角色 | 它是基础、核心、桥接、对比还是扩展内容？ |
| 前置 | 理解它必须先知道什么？ |
| 首次讲解位置 | 哪一章负责准确定义并完整讲解？ |
| 后续复用 | 学习者会在哪里再次使用它？ |
| 证据 | 哪个实验、诊断、输出、状态轨迹或规范关系能够验证？ |
| 实践 | 学习者需要预测、修改、实现、调试、比较还是选择？ |
| 完成标准 | 什么可观察表现允许进入下一阶段？ |
| 来源职责 | 哪类权威资料支持当前结论？ |

覆盖清单既包含概念和机制，也包含当前目标需要的语法、常用操作、工具和工程能力。不要用章节数量、代码长度或 API 数量代替覆盖质量。

## 建立前置关系与学习顺序

把节点标记为“当前必须理解”“必要前置”“近期后续”或“远期扩展”，再按依赖关系形成主线。一个章节只应使用：

1. 已经完整讲过的内容；
2. 本章正在完整讲解的内容；
3. 为读懂示例而临时借用、并明确标注为后续主题的最小语法。

不要按官方文档目录、API 字母顺序或教程章节数量直接生成学习顺序。“高阶”由前置依赖、模型层次、实现深度和工程决策难度决定，不等于更偏门的 API。

若主题是编程语言，读取 [programming-language-learning.md](programming-language-learning.md)，用其中八个覆盖维度检查整门语言；若主题包含类型、集合、标准库、SDK 或命令族，再读取 [syntax-and-api-teaching.md](syntax-and-api-teaching.md) 建立操作清单。

## 控制章节粒度与范围完整性

优先把共享同一问题、模型、前置、示例和完成任务的内容保留在一个连贯章节。篇幅长、标题多或方法多本身不是拆分理由。

出现以下情况时再拆分：

- 第二个主题需要不同的心智模型、生命周期或前置知识；
- 一个示例被迫同时引入多个尚未讲解的核心机制；
- 自检开始测试多个互相独立的能力；
- 一条分支可以独立学习和验证，不依赖当前主线；
- 当前范围无法在一篇内容中保持可读且完整。

声明了本章范围后，要完整覆盖支撑该范围的核心概念与操作。内容过多时拆成连续章节并说明后续归属；不要为了篇幅静默省略，也不要机械地“一方法一篇”。

## 选择资料并区分证据职责

- 用规范、标准、官方参考和正式设计材料确认“是什么、保证什么、为什么选择”；
- 用官方教程、成熟项目文档和当前版本测试确认“怎样使用、当前环境怎样表现”；
- 用高质量教材或二手材料辅助学习顺序、直觉和练习，但不替代正式定义；
- 对库、框架、SDK、API、CLI 和云服务，查询当前权威文档并标明版本或环境；
- 资料冲突时，缩小成一个可复现差异，区分规范要求、实现行为、版本事实和工程建议。

没有可靠资料或没有实际运行时，明确标注不确定性、教学推断、预期结果和验证步骤。

## 形成实践阶梯

根据主题选择必要层级，不强制每章全部包含：

1. **最小真实形态**：看见语法、类型、状态或调用长什么样；
2. **预测微实验**：先依据规则预测，再运行或推演；
3. **机制追踪**：沿执行、数据、类型、控制流或生命周期解释结果；
4. **边界变式**：只改变一个条件，预测结论怎样变化；
5. **接近真实模块的片段**：在自然任务中使用当前能力；
6. **修改、实现或调试**：不照抄示例完成同类任务；
7. **项目级迁移**：只有前置能力已经形成时才讨论规范或架构。

完成标准优先使用可观察动词：定义、预测、追踪、区分、修改、实现、调试和选择。成功运行示例只证明示例运行过，不能单独证明掌握。

- 语法、方法、标准库、API 或命令族的操作覆盖：读取 [syntax-and-api-teaching.md](syntax-and-api-teaching.md)。
- 最终讲解结构和可见标题：读取 [teaching-style.md](teaching-style.md)。
- 可运行代码、命令和结果证据：读取 [code-style.md](code-style.md)。
