# 代码与可执行证据

用于可复现实验、需要环境说明的示例或复杂结果呈现。操作覆盖由 [语法与操作](syntax-and-api-teaching.md) 负责；这里关注例子能证明什么，以及怎样可靠地展示它。

## 明确示例与执行范围

区分可独立运行的程序、需要上下文的片段和伪代码。使用对应的代码围栏；片段说明缺少的调用上下文，伪代码标明其性质，不把示意写法声称为可运行程序。

只保留决定行为的输入、初始化、调用和状态，但不省略影响正确性的错误处理、资源清理或事务边界。环境或版本影响结果时说明它们。

提供代码不是执行授权。需要运行时先确认属于已授权环境；不为验证教学示例擅自安装依赖、连接真实数据库、变更服务或修改用户数据。不能安全执行时，提供推演或预期结果并说明验证条件。

## 使证据支持具体结论

- 说明输入和初始状态，以及哪条规则决定关键步骤。
- 同时关注返回值、输出和原状态，避免只展示一个方面。
- 结果确实运行过才标为“实际运行结果”；否则使用“预期结果”或“推演”。
- 不确定顺序、随机性或环境依赖存在时，说明哪些关系有保证，而不是给一个假定的唯一输出。
- 一次实现观察不能证明规范保证，测试通过不能证明所有输入都正确。

解释放在靠近代码或输出的位置，不用大段代码代替机制说明。标识符有意义且一致，采用目标语言或项目的惯用风格。

## 根据保证层解释结果

只有区别影响当前结论时，明确标注证据所在层：

- 编译时检查或诊断说明什么被静态接受、拒绝或推导。
- 运行时证据说明实际的对象、调用、状态或调度行为。
- 外部输入验证说明不可信数据如何被检查，不能由静态类型声明替代。
- 性能测量依赖环境、数据规模与负载，不能把复杂度或单次计时当成完整性能结论。

相关边界应贴近示例解释，不要求每个片段重复全部分类。

## 注释与错误示例

注释只补充不明显的意图、约束或选择，不逐行翻译语法。正文承担概念定义与主要推理。

有意展示错误写法时，明确它为什么错误；用户未要求独立作答时，紧邻提供修正或解释。涉及外部输入时，不把不安全的字符串拼接等做法作为正常示范。

## SQL 示例

仅在涉及 SQL 时应用；项目或用户已指定的规范优先。

- 说明影响结论的数据库方言与版本。
- 默认关键字大写、表列名使用小写蛇形命名，主要子句分行，以分号结束。
- 结果顺序影响演示时显式排序；不把无排序查询的一次输出当作稳定顺序。
- 查询契约需要明确时列出所需列；讲解通配符等相关语法时可以使用它。
- 默认使用显式 JOIN 并写明连接类型，多表查询限定列来源，别名保持简短且有意义。
- 讲解连接时提供足够的数据以观察匹配、重复、未匹配行与 NULL；解释外连接中条件位置可能改变结果。
- 外部值使用参数绑定；涉及事务或资源生命周期的主题保留必要边界。

区分逻辑语义与物理执行。不要把 SQL 文本顺序当作优化器实际执行顺序，也不要用一次执行计划推广所有数据规模。

## 算法与结果呈现

算法围绕输入输出、核心规则或不变量、具体推演、正确性依据及复杂度前提组织；代码在用户要求或确实帮助理解时提供，不强制每个算法问题都附实现。

小型表格结果可用 Markdown 表格，终端输出用文本代码块。解释哪些值出现、哪些没有出现，以及哪个规则导致差异；只展示检验当前主张所需的输出。
